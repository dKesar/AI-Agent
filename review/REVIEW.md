# Краткая рецензия курса и формат подачи

## Исходное состояние

Материалы имели связный технический кейс, разумный тайминг и тестируемое ядро. Однако входные требования — Python, словари, исключения и терминал — противоречили задаче обучить человека с нуля. Командный результат мог скрыть отсутствие личного навыка. Зелёный CI подтверждал работу программы, но не усвоение.

## Что изменено

Основной маршрут не требует написания кода: первый запуск с переводом результатов, полностью разобранный пример, собственное правило через мастер, пять ручных проверок и одно исправление. Есть словарь, подсказки по нарастанию, контрольные точки, индивидуальная демонстрация и самостоятельное повторение после занятия. Задания Python оставлены отдельным дополнительным маршрутом.

Цели, расписание, практики, формы сдачи и рубрика согласованы. Участник получает конкретный результат — собственную копию памятки, задачу и наблюдавшийся ответ. Границы результата объяснены: это настройка симулятора, а не обучение нейросети. Демонстрация настоящей модели готовится преподавателем отдельно.

## Оставшиеся ограничения

Терминал и правка JSON всё ещё создают некоторый порог. Для очного занятия он компенсируется предварительной подготовкой и показом первой правки. Для полностью самостоятельного массового прохождения желателен браузерный редактор полей и визуальный журнал. Нельзя утверждать «особо высокую усвояемость» без пилота с настоящими новичками и отсроченного повторения.

За 6 академических часов реалистичны общее представление, настройка готового решения и базовые проверки. Самостоятельное создание промышленного LLM-агента выходит за этот объём.

## Рекомендация по форме

**Для текущего очного курса: PowerPoint с заметками ведущего + локальный практикум + краткая памятка участника.** По запросу автора подготовлена [визуальная лекция](../lectures/visual/README.md) на 90 минут: 32 слайда с редактируемыми схемами, вопросами и двумя таблицами. Полный сценарий встроен в заметки PowerPoint и доступен отдельным текстом.

Для самостоятельного прохождения следующим этапом может стать небольшой HTML-сайт с упражнениями. Сайт пока не создавался и не публиковался.

| Вариант | Преимущества | Ограничения | Вывод |
|---|---|---|---|
| Только Markdown в GitHub | Проверяемые исходники, история, легко обновлять | Много файлов и слабая последовательность для новичка | Хорош как основа и версия для разработчика |
| HTML-сайт с небольшими упражнениями | Пошаговый маршрут, раскрывающиеся подсказки, форма своего правила, наглядные действия | Нужно поддерживать связь с исходными материалами; работа Python требует локального запуска или отдельного исполнения | Лучший следующий шаг для этой программы |
| Полная учебная платформа | Аккаунты, группы, задания, сохранение результатов преподавателю | Сервер, поддержка, данные пользователей; больше стоимости разработки | Оправдана позже при повторных потоках и учёте результатов |
| PowerPoint с заметками и локальным практикумом | Крупные схемы для группы, готовый сценарий, личная работа руками | Нужен ведущий и подготовленный компьютер | Основной формат текущего очного курса |

На сайте достаточно: маршрут шести блоков; карточки «объяснение → пример → попробуйте → обратная связь»; форма правила; демонстрация шагов; самопроверка; экспорт работы. Если браузерная демонстрация лишь повторяет симулятор на JavaScript, её нужно так и обозначить, а не считать запуском Python или LLM.

Источником истины остаются материалы и данные в репозитории. Предпочтительна сборка страниц из этих же Markdown/JSON, чтобы сайт и Git не расходились. Личные аккаунты и серверное хранение не нужны, пока преподавателю достаточно экспорта работ. Если потребуется настоящее LLM-выполнение в браузере, ключ API должен оставаться на сервере, а не в публичном HTML.

## Как подтвердить качество

Пилот с 3–5 новичками: измерить время до первого результата, число подсказок, долю самостоятельных настроек и качество объяснения. Затем дать другую тему без готового примера. Через несколько дней повторить проверку. Малый пилот выявляет проблемы интерфейса и объяснений, но не доказывает статистически эффективность методики.

Критерий принятия для автора: каждый участник должен показать личный запуск, найти источник, объяснить уточнение и назвать оставшуюся ошибку. Если этого нет, дорабатывать конкретный шаг, а не добавлять терминов и слайдов.
