## Практика 1

Ожидаемые траектории:

| Случай | Инструменты | Итог |
|---|---|---|
| normal | search_policy → get_sla → prepare_draft | IT-01, 24 часа |
| access | search_policy → get_sla → prepare_draft | IT-02, 24 часа |
| ambiguous | search_policy → request_clarification | needs_input |
| unknown | search_policy → escalate_to_human | needs_human |
| missing | Нет вызовов | needs_input |
| tool_error | Две попытки поиска | needs_human |

В `sim` действие выбирает `Simulator.choose`, в `llm` — API-адаптер. Исполнение одинаковое: `Toolkit.execute`. Итог проверяет `run`; содержательные предварительные условия черновика проверяет `_dispatch`.

## Практика 2

[estimate_cost.py](estimate_cost.py) читает цены из одного JSON-источника, проверяет вход до умножения и возвращает результат со ссылкой `CATALOG-01`.

Проверка `type(quantity) is int` исключает `bool`. Проверка имени перед доступом к словарю исключает `KeyError` и некорректные типы ключей. Цены целочисленные: для задачи с дробными денежными суммами предпочтительны минимальные единицы валюты или Decimal с явно определённым округлением.

```bash
python -m scripts.check_exercise --solution
python -m agent_lab --case procurement --extension solution
```

Получаем 140000 рублей за два учебных ноутбука. `prepare_draft` требует расчёт, если расширение подключено и задача содержит товар. Расчёт не означает согласование или покупку.

## Практика 3

Пример записи регламента:

```json
{"id":"TR-01","title":"Командировка","keywords":["командиров"],"rule":"Для командировки укажите цель, даты, место и согласование руководителя."}
```

Пример двух тестов — [test_travel_example.py](test_travel_example.py). Он не входит в основной автопоиск тестов: скопируйте его в `tests/test_my_case.py` после добавления регламента. В исходной базе `TR-01` намеренно отсутствует, поскольку это задание учащегося.

Почему отрицательный тест нужен отдельно? Успешное получение `TR-01` не доказывает, что исполнитель отклонит чужой идентификатор. Разные утверждения требуют разных проверок.

## Что считать хорошим объяснением

«Инструмент вызван трижды» недостаточно. Хороший ответ: «Черновик разрешён после получения одного регламента и SLA. Подстановка другого идентификатора отвергается исполнителем независимо от решения модели. При нескольких регламентах требуется уточнение. Симулятор проверяет эту механику, но не качество LLM».
