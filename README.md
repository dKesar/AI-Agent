# ИИ-агенты: от задачи до проверяемого прототипа

Учебный комплект на **6 академических часов**: 90 минут лекции и 180 минут практики и контроля. Материалы на русском языке. Вся базовая практика работает локально на **Python 3.10+ без сторонних пакетов, интернета и API-ключей**.

Сквозной пример — помощник по внутренним обращениям: найти учебный регламент, получить срок первого ответа, подготовить черновик либо запросить уточнение. Реальных отправок, покупок и изменений во внешних системах нет.

## Начать за пять минут

Скачайте репозиторий через **Code → Download ZIP**, распакуйте и откройте терминал в папке, где находится этот README. Git для прохождения занятия необязателен.

```bash
python --version
python -m scripts.check_environment
python -m agent_lab --case normal
python -m agent_lab --case ambiguous
python -m unittest discover -s tests -v
```

На Windows можно заменить `python` на `py -3`, на macOS/Linux — на `python3`. Установка через `pip` не требуется. Все команды ниже выполняются **из корня проекта**. Если нужна работа с Git: создайте личную ветку `git switch -c practice/your-name` после клонирования; не выполняйте эту команду в скачанном ZIP.

Обычный случай завершится `awaiting_review`, покажет три вызова и источники `IT-01`, `SLA-01`. Неоднозначный случай завершится `needs_input` с вопросом. `Отправлено: нет` — ожидаемое поведение.

## Кому подходит

Базовый маршрут рассчитан на учащихся, знакомых с функциями Python, словарями, `if`, исключениями и запуском команд. Необходимы компьютер на пару и редактор. Предположение об уровне нужно подтвердить до занятия: это не курс Python с нуля. Для группы без программирования предусмотрен [резервный сценарий](instructor/offline.md).

К концу занятия учащийся сможет объяснить цикл агента, отличить выбор действия от его исполнения, добавить инструмент с контрактом, проверить успешный и проблемный сценарии и обосновать необходимость LLM.

## Два режима

| Режим | Кто выбирает действие | Для чего нужен |
|---|---|---|
| `sim` (по умолчанию) | Условия в `Simulator.choose()` | Воспроизводимо изучать инструменты, состояния и ошибки |
| `llm` | Настоящая модель через Responses API | Наблюдать решения модели и сравнивать повторные запуски |

**Симулятор не является языковой моделью.** Даже идеальный результат его тестов ничего не доказывает об устойчивости LLM. [Подключение модели и демонстрация](examples/llm.md) — отдельный этап, который преподаватель готовит заранее. Текущий комплект не содержит выдуманных записей «реальных» API-запусков.

## Полезные команды

```bash
python -m scripts.run_cases
python -m scripts.run_cases --output outputs/cases.json
python -m agent_lab --case access --json
python -m agent_lab --case normal --steps 1
python -m agent_lab --case normal --seconds 0
python -m agent_lab --task examples/custom_task.json
python -m scripts.check_exercise
python -m scripts.check_exercise --solution
python -m agent_lab --case procurement --extension solution
python -m scripts.check_links
```

`check_exercise` без `--solution` **должен падать до выполнения задания**: он проверяет заготовку учащегося. Основные тесты и CI проверяют готовый пример и эталон, поэтому на чистой копии должны проходить.

Коды завершения CLI: `0` — обработанный результат (в том числе уточнение или передача человеку), `1` — ошибка исполнения/лимит/некорректный вход, `2` — ошибка параметров запуска или конфигурации. Для оценки бизнес-результата читайте `status`, а не только код процесса.

## Ограничения учебных данных

Все регламенты, цены и SLA вымышлены. SLA означает срок **первого ответа**, а не решения заявки. Поиск выполняется по префиксам слов из [policies.json](data/policies.json); это прозрачный учебный retrieval, не семантический поиск и не полноценная RAG-система. Ответ собирается из проверенных полей шаблоном; LLM выбирает инструменты, но не пишет итоговый текст свободно.

Метки «проверка человеком» обозначают результат этого прототипа. Здесь нет авторизации пользователей, системы согласований и кнопки фактической отправки.
