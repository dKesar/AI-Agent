# Подключение настоящей модели

[README](../README.md) · [Архитектура](architecture.md)

Нужен доступный вам OpenAI API-аккаунт, API-ключ и идентификатор модели с поддержкой Responses API и function calling. Подписка на ChatGPT сама по себе не является конфигурацией API. Выбранную модель и доступность сервиса преподаватель проверяет заранее; обход ограничений доступа в практикум не входит.

Базовая практика остаётся офлайн. Для API используйте только вымышленные учебные заявки. В режиме `llm` содержимое задачи и результаты инструментов передаются провайдеру модели. Запрос содержит `store=false`, но это не обещание отсутствия всех видов серверного хранения: применяются условия API-провайдера.

## Настройка без сохранения ключа в истории команд

В Bash:

```bash
read -s -p "API key: " OPENAI_API_KEY
export OPENAI_API_KEY
export OPENAI_MODEL="идентификатор_доступной_вам_модели"
python -m agent_lab --mode llm --case normal --json
unset OPENAI_API_KEY
```

В PowerShell 7:

```powershell
$secret = Read-Host "API key" -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
$env:OPENAI_MODEL = 'идентификатор_доступной_вам_модели'
python -m agent_lab --mode llm --case normal --json
Remove-Item Env:OPENAI_API_KEY
```

Приложение читает переменные окружения и **не загружает `.env` автоматически**. [.env.example](../.env.example) — справка по именам. Не записывайте действующий ключ в код или общий репозиторий. После завершения удалите переменную из сессии.

## Демонстрация преподавателя

1. Запустите `normal` и сравните действия с симулятором.
2. Запустите `ambiguous`: модель должна задать вопрос через `request_clarification`.
3. Запустите `unknown`: ожидается передача человеку.
4. Запустите `injection`: оцените выбор модели и отдельно работу исполнителя.
5. Повторите выбранные случаи хотя бы три раза. Запишите модель, дату, статусы, источники, число вызовов и токены в [таблицу](../templates/test_report.md).

```bash
python -m agent_lab --mode llm --case ambiguous --json
python -m agent_lab --mode llm --case injection --json
python -m agent_lab --mode llm --case procurement --extension solution --json
```

Не запускайте дополнительные прогоны без учёта тарификации. В приложении ограничены шаги и выходные токены запроса, но **нет точного денежного лимита**; бюджет задаётся также средствами аккаунта. `usage` показывает фактически возвращённые API счётчики токенов для успешных разобранных ответов. Это не полный биллинговый отчёт при сетевых сбоях.

## Если API не сработал

| Диагностика | Что проверить |
|---|---|
| `missing_api_configuration` | Обе переменные окружения |
| `authentication_failed` | Действительность ключа |
| `access_denied` | Доступ аккаунта к ресурсу |
| `model_or_endpoint_not_found` | Идентификатор и доступность модели |
| `rate_or_quota_limit` | Квоту, лимит запросов и биллинг |
| `bad_api_request` | Поддержку параметров выбранной моделью |
| `incomplete_or_failed_response` | Лимит генерации/сбой; не считать незавершённый ответ готовым |
| `request_timeout` / `network_error` | Сеть и доступность сервиса |

При недоступности API проводите практику на симуляторе и явно отметьте, что поведение LLM не проверялось. Можно заранее сохранить **настоящий** успешный запуск и показать его как запись с датой и моделью. Не переименовывайте результат симулятора в «запись LLM».

Тесты в [test_adapter.py](../tests/test_adapter.py) не расходуют токены: они подставляют HTTP-ответы. Они проверяют перенос `call_id`, историю, ошибки и бюджет запроса, но не подтверждают реальный доступ к модели.

Официальная спецификация: [Function calling](https://developers.openai.com/api/docs/guides/function-calling). Адаптер сохраняет элементы `output` между запросами; для stateless reasoning запрашивает `reasoning.encrypted_content`.
