# Практика 3. Проверить и улучшить своего помощника — 45 минут

Основной маршрут новой программы — [журнал опытов в браузере](browser.md). Ниже — дополнительный локальный вариант.

[Предыдущая](02_tools.md) · [Далее](04_defense.md) · [Автотесты для знающих Python](developer_controls.md)

**Задача:** проверить собственное правило на разных входах и исправить один наблюдаемый недостаток. Открывайте JSON обычным текстовым редактором, не Word. Преподаватель сначала показывает одну правку.

| Минуты | Что делаем |
|---|---|
| 0–10 | Разбираем готовую проверку обычного случая |
| 10–25 | Самостоятельно выполняем ещё четыре проверки |
| 25–35 | Исправляем ключ или вопрос, повторяем неудачный случай |
| 35–45 | Заполняем отчёт и объясняем пределы поиска |

## Как менять только вопрос

Откройте `task.json` в папке вашего примера. Он имеет такой вид:

```json
{"question":"Как оформить командировку?","priority":"normal"}
```

Изменяйте текст внутри кавычек после question, сохраняя сами кавычки. Сохраните файл. Выполните **команду, которую мастер напечатал в конце создания вашего примера**. Например, для первой папки:

```bash
python -m agent_lab --task outputs/my_case/task.json --policies outputs/my_case/policies.json
```

Для следующих папок замените `my_case` на фактическое имя. Запуск не перезаписывает прежний result.json: новый результат виден на экране; запишите его в отчёт. Если неудобно работать с файлами, преподаватель помогает открыть редактор; сам вопрос и ожидаемый результат выбираете вы.

## Пять проверок

**До каждого запуска** запишите ожидание, после — результат и объяснение.

| № | Что проверить | Пример для командировки | Ожидание |
|---|---|---|---|
| 1 | Обычный запрос | Как оформить командировку? | TR-01, черновик |
| 2 | Другие слова, тот же смысл | Еду в служебную поездку | При исходном ключе совпадения нет; это недостаток поиска |
| 3 | Чужая тема без ключей | Как оформить отпуск? | Передача сотруднику |
| 4 | Две темы | Командировка и восстановление доступа | Уточнение |
| 5 | Лимит | Тот же вопрос с параметром --steps 1 | step_limit: поиск выполнен, черновика нет |

Срочность проверяется дополнительно: смена priority на urgent сохраняет источник и меняет срок на 4 часа. Для неоднозначного вопроса нужны совпадения с двумя реальными правилами памятки.

Примеры показывают принцип. Для собственного правила подберите свои формулировки. Если случай 2 неожиданно сработал, выясните, какой ключ совпал. Это лучше, чем подгонять наблюдение под ожидание.

## Одно улучшение

Для командировки добавьте в её список keywords ещё один ключ:

```json
"keywords": ["командиров", "поездк"]
```

Сохраните `policies.json`, повторите случай 2 и затем случай 1. Оба должны выбирать TR-01. Вы исправили конкретное ограничение, не переписывая программу. Если ваше правило другое — добавьте ключ для вашей нераспознанной формулировки.

<details><summary>Если JSON не читается</summary>

Проверьте обычные двойные кавычки, запятые между полями и элементами списка, закрывающие скобки. Программа сообщит об ошибке загрузки. При повреждении копии создайте новый пример через мастер; исходная памятка курса не изменялась.

</details>

**Важное ограничение:** ключ «поездк» может также совпасть с поездкой на отдых. Наш поиск не понимает смысл. Добавьте один такой отрицательный пример в замечания. Улучшение на двух примерах не доказывает высокое качество везде.

**Готово, если:** есть пять наблюдений, одно изменение и повторная проверка; участник может объяснить, какой недостаток остался. Это ручные испытания. Не называйте их автоматическими тестами Python.
