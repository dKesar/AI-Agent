## Контракт

`estimate_cost(item, quantity)` читает [catalog.json](../data/catalog.json) через `agent_lab.core.load_data`. Названия товаров: `laptop`, `monitor`, `keyboard`. Все цены вымышленные.

- `item` — строка, присутствующая в каталоге.
- `quantity` — целое число от 1 до 100 включительно. `True`, `2.5` и `"2"` недопустимы.
- Успешный результат: `{"total_rub": <целое число>, "source": "CATALOG-01"}`.
- При неверном товаре поднимите `ToolError("unknown_item")`; при неверном количестве — `ToolError("invalid_quantity")`.
- Функция ничего не покупает и не отправляет; не добавляйте ввод с клавиатуры или сетевой запрос.

```bash
python -m scripts.check_exercise
python -m agent_lab --case procurement --extension student
```

Первый запуск проверки до выполнения задания должен быть неуспешным. После реализации должны пройти шесть тестов, а полный сценарий показать `estimate_cost`, сумму 140000 и источник `CATALOG-01`.

Подсказки по нарастанию:

1. Начните с чтения словаря цен и умножения на количество.
2. Проверьте тип товара **до** проверки его наличия в словаре: список не является допустимым ключом.
3. `isinstance(True, int)` возвращает `True`; здесь полезна точная проверка типа.

Покажите партнёру, где исполнитель проверяет соответствие товара и количества исходной заявке. Почему правильный расчёт для другого товара всё равно должен быть отклонён?

**Критерий готовности:** шесть проверок проходят без изменения тестов; полный сценарий использует студенческую функцию; вы объясняете разницу между вычислением суммы и разрешением покупки.
