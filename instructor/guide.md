# Сценарий преподавателя

[Главный маршрут](../README.md) · [Рубрика](rubric.md) · [Ключ теста](quiz_key.md)

## До занятия

Подтвердите уровень группы: функции, словари и исключения Python. Определите четыре команды и обеспечьте один компьютер на пару. Уточните доступность Python, редактора и проектора. Скачайте копию заранее: базовой практике сеть не нужна.

Пройдите путь учащегося из чистой папки. Выполните `python -m scripts.check_environment`, основные тесты, `run_cases`, `check_exercise --solution` и `check_links`. Проверьте, что обычный `check_exercise` падает на незаполненной заготовке: это часть задания, а не сломанный комплект.

Если демонстрируете LLM, отдельно выполните [подготовку API](../examples/llm.md). Используйте свой ограниченный учебный ключ в окружении преподавателя; не раздавайте общий ключ в репозитории. Запишите реальные прогоны заранее, если опасаетесь нестабильного доступа. Не обещайте демонстрацию модели, пока не проверили её.

Ключ теста и эталоны видимы всем, кто имеет доступ к репозиторию. Просьба «не смотреть» подходит для обучения, но не обеспечивает защищённый экзамен. Для формального контроля подготовьте отдельный вариант вопросов вне общего репозитория.

## Расписание ведущего

| От начала | Блок | Контрольная точка |
|---|---|---|
| 00:00–00:45 | Лекция 1 | Участники различают workflow и выбор модели |
| 00:45–01:30 | Лекция 2 | Могут объяснить контракт и проверку прав |
| 01:30–01:45 | Перерыв | Подготовить терминалы |
| 01:45–02:30 | Практика 1 | Есть журнал и объяснение неоднозначности |
| 02:30–03:15 | Практика 2 | Функция проходит контрактные тесты |
| 03:15–03:30 | Перерыв | Сверить продвижение команд |
| 03:30–04:15 | Практика 3 | Новый регламент и два теста |
| 04:15–05:00 | Контроль и защита | Паспорт, отчёт, индивидуальный результат |

Тайминг внутри каждого блока находится в соответствующем файле. В практиках 1–3 меняйте роли оператора и проверяющего. Для группы более четырёх команд вместо четырёх общих защит проведите 20 минут взаимозащиты парами: одна команда показывает, другая оценивает по рубрике, затем меняются. Преподаватель выборочно проверяет спорные оценки.

## Открытие — готовый текст

«Сегодня мы исследуем систему, которая выбирает действия, вызывает инструменты и проверяет результат. Сначала используем прозрачный симулятор, затем увидим, что меняется при подключении языковой модели. Наша цель — объяснить и проверить поведение, включая ситуации, когда полезно остановиться и спросить человека».

Входная диагностика: попросите объяснить разницу между «модель написала, что письмо отправлено» и «письмо действительно отправлено». Это устное обсуждение, не часть оценки.

## Демонстрации

1. `normal` → `access`: разные вопросы приводят к разным источникам.
2. `ambiguous`: после поиска уточнение становится корректным результатом.
3. `injection`: посторонний текст виден в данных, но не получает полномочий.
4. Тест `test_forbidden_action`: проверка исполнителя независима от симулятора.
5. `--steps 1`: объяснить, почему остановка по бюджету не является завершённой задачей.
6. LLM, если доступна: показать одну реальную траекторию и сравнить с симулятором; не скрывать неудачи.

## Типичные затруднения

| Симптом | Причина / помощь |
|---|---|
| `No module named agent_lab` | Терминал открыт не в корне проекта |
| `python` не найден | Попробовать `py -3` или `python3`; при отсутствии Python — резерв |
| `NotImplementedError` в задании | Заготовка ещё не выполнена |
| CI зелёный, студенческий инструмент не готов | CI проверяет готовый эталон; для работы учащегося нужен `check_exercise` без флага |
| «Симулятор устойчив к любым атакам» | Разделить тест приложения и свойства LLM |
| «Нужно добавить много агентов» | Попросить измеримую причину усложнения |
| `needs_input` считают аварией | Обсудить уточнение как полезный результат |

## Завершение

Соберите формы сдачи. Проверьте код, отчёт и способность объяснить результат. Отдельно отметьте, была ли реально запущена LLM. Попросите каждого назвать один случай, где обычный код предпочтительнее агента.

При отсутствии техники используйте [бумажный сценарий](offline.md). Его результаты нельзя отмечать как выполненные программные тесты.
